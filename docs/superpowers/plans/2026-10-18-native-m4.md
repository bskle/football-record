## 4. 统一红绿、提交和证据规则

每个下面的 commit slice 按五个动作执行：先写列出的失败测试 → 用列出的命令确认目标失败且原因正确 → 实现本 slice 的固定类型/事务或 driver 行为 → 重跑该测试与相关回归 → 按明确路径提交 Conventional Commit（默认无 scope），body 记实际命令/结果/限制。不得先写完全部模块再补测试；测试以故障后重开、跨进程/网络、原 bytes、持久状态为断言，不镜像私有实现。测试代码中的 `fixture` 是各任务明确列出的 support 文件，须在该 slice 内实现，不可引用仓外未知脚本。

每任务的树外目录使用 `native-validation/NATIVE-<ID>/`；保留六项 Git 输入（status、head、base、target、diff、worktrees）、命令原输出、工具版本、输入 SHA manifest、红阶段和绿阶段。每轮测试总数只报该轮，历史分层证据分开。两位非作者按 exact source/final SHA 审阅后，主代理 `--no-ff` 合并并核对实际 merge；设备无影响的纯控制/协议任务解释真机不适用。生产能力门槛未到的分支保留，不以编译通过代替真实验收。

```sql
INSERT INTO requests(account_id,request_id,operation,request_digest,result) VALUES(?,?,?,?,?);
COMMIT;
```
