# 球历 M2 采集、会话与原生记录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement approved child plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本文冻结技术拆分和跨任务合同；每位实现负责人先在自己的任务树写可执行子计划，再写代码，不在总计划重复完整实现。

**Goal:** 接通先保存后反馈的双端原生记录页面、采集元数据持久化、真实 Workout 适配与同场恢复，并按证据层级验收 M2。

**Architecture:** 在现有 MatchCore SwiftPM 包扩展 MatchStore、新增 MatchSession product/target。实际复用的 WorkoutCapture 包提供两平台适配；唯一 UI/工程集成者装配共享展示和 App。业务事务与 HealthKit 通过持久采集操作对账，不宣称跨系统原子性。

**Tech Stack:** Swift 6、SwiftUI、系统 SQLite3、XCTest、HealthKit、Core Location；最低 iOS 17 / watchOS 10；不引入第三方 SDK。

## 3. 交接冻结点

具体签名、状态和错误见[会话采集合约](../../native/contracts/m2-session-capture.md)。006/007子计划按合同落地；如编译发现须调整，由主代理先审合同变更并同步依赖，再派008/009。

- UI成功反馈/触觉只来自COMMIT后的receipt与snapshot；LiveMatchRecorder仅staging。完整请求的commandID、时间、事件/操作ID、原expectedGeneration固定，响应丢失原样重试。
- 单机事实与采集变更同事务落未路由业务outbox；不造phone/空目标/随机peer，不放弃outbox。M3有真实peer后原子路由为稳定packet，仍核验持久ACK。
- v1→v2迁移、append-only CaptureRevision、持久CaptureOperation归006。保留旧canonical字节、command hash、packet checksum/receipt；不得无条件加空数组破旧哈希。采集digest变化使旧完整保存凭据失效；旧snapshot/旧saveCompletionEvidence也须防止绕过v2 proof，不为改hash伪造业务事件。
- 业务facts/outbox/pending operation COMMIT→事务外gateway→真实观测/关联revision和操作结果COMMIT。第二次DB失败按原operationID对账，不盲建Workout。
- 每场业务提交队列防actor await重入；采集异步返回重读终结状态，终结后只收尾原片段，不续采。上下场不触Workout pause；业务与采集暂停失败分别展示。
- 恢复只靠matchIDs+snapshot，不存第二currentMatch索引。多活动候选、错误本机设备、终结或阻塞诊断不接管；观测未知保持nil。
