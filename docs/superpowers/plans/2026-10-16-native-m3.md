# M3 持久设备同步实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this approved child plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本文冻结交付、接口、测试和所有权，不内嵌整套未来实现。

**Goal:** 先交付可自动验证的持久 v2 业务同步与状态 UI，再以临时设备包验证配对 iPhone / Watch 的断连、后台与恢复。

**Architecture:** 在现有 MatchStore 上 additive schema 3 保存不可变完整快照包、原 outbox 映射、收包事务及持久 ACK。纯 MatchSync 服务复用当前 Session 的单一仓储 facade 和同场队列；DeviceSync 独立封装 WCSession，生产可信 peer 在 M4 前 unavailable。

**Tech Stack:** Swift 6、系统 SQLite3、XCTest、SwiftUI、WatchConnectivity；最低 iOS 17 / watchOS 10；当前 Xcode 27.0 / Swift 6.4。

## 3. 固定实现选择与交接条件

- 每原业务 outbox 映射一个稳定 v2 包，首次路由事务冻结当前完整 descriptor/events/capture ancestry；原 business_outbox state / raw / registry / command receipt 不改。新表记录 immutable route、包序和 ACK；原命令路由后仍能原样重试。
- capture 完整闭包按拓扑校验后 append-only union。r2 自带 r1 先到、再到旧 r1 / 重放 r2 都幂等；同父双子、跨 match、同 ID 异字节才 blocking。原包缺帧不进入业务事务、不制造缺父诊断。
- provider 验实际持久 local/remote IDs、账号、配对和 epoch，先于 route/receive/ACK/send；WC 可达/配对状态和 checksum 不作账号认证。生产始终 unavailable；Debug 两隔离数据库/稳定身份 fixture 只测协议。
- 新模块 MatchSync 实际注册于现有 SwiftPM 包，依赖 Core/Store；共用 DTO / repository / inbound coordinator 在 Store 可见边界，Session 不反向依赖 MatchSync。当前 facade 内只有一个 Store/连接；同场接收与 execute 共用队列。
- 原 payload/receipt 与本机权威 descriptor 投影分开验证。incoming releasedConfirmed / completion proof / 自报 verifiedNetwork 不可信；不得完成或放锁，本机可信状态不被旧 held 包回退。M4真实证明用独立入口。
- COMMIT 后 publish + 可恢复地唤醒原本机采集收尾；同包重放也重发通知、重开 terminal 扫描补清理。SDK/网络 await 不占 SQL 或同场队列；不接管、不新 start、不新 token、不复活。
- 分片与 ACK 控制重试遵合同定额 / 时间；完整包校验后一次接收事务。真 `transferFile` 不支持 Simulator，配对真机证据留018。

014交接必须是可编译签名 + migration fixture + exact head/merge证据；015交接必须是可注入 service/transport/trust + 同 facade 的 Session 桥 + 故障测试。未达交接条件不派016/017。
