# 原生 V1 开发总计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement approved child plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本文是里程碑母计划，不是全量逐行代码实现计划；开发前必须先完成对应可执行子计划。

**Goal:** 交付 iPhone + Apple Watch 的可信比赛记录闭环，通过连续三场真实比赛验收后发布免费 V1。

**Architecture:** 共享事件引擎从比赛事实重算比分、计时、出场和生涯；本地事务日志与 outbox 保证先保存、后反馈，并驱动幂等跨设备同步。Watch 为主要记录端，单场绑定唯一 recordingDeviceID；HealthKit、CloudKit 私有业务数据、最小账号与锁后台各守既定边界。

**Tech Stack:** Swift 6、SwiftUI、XCTest、HealthKit、Core Location、WatchConnectivity、MapKit、CloudKit 私有数据库、AuthenticationServices、Swift Charts；最低 iOS 17 / watchOS 10。本地事务仓储由 M1 子计划采用系统 SQLite（无外部包）；最小后台运行环境在对应子计划中确定，不在母计划指定外部服务商。

## 2. 已确认的交付边界

- 一个账号同一时间最多一场活动比赛；单场只有一个 recordingDeviceID，其他手机或 Watch 不接管采集。iPhone 与 Watch 共用业务规则，不代表同时写入。
- 开始必须联网取得后台原子锁；后台不可用禁止开始。取得锁后可离线记录与结束，后台确认终结前锁仍保留。记录设备可以是绑定的 iPhone 或 Watch，以 Watch 比赛体验优先。
- 点击先事务持久化，再反馈；事件唯一 ID、稳定请求 ID、revision、checksum、幂等键和持久化确认贯穿同步。比分与生涯均从基础事实重算。
- 比赛与上下场独立；暂停冻结比赛和上场计时，恢复保持上场状态；下场不暂停比赛或 Workout。重复上下场保留事实并标异常，结束闭合未结束出场。
- Watch 第一页合并比分、双时钟、身体数据和两个操作位；第二页四个至少 44pt 的按钮为“我进球、我助攻、进球、失球”。单击保存、1000ms 防重复、最后一条快记持续可撤销；乌龙、姓名与完整时间线放到赛后编辑。
- iPhone 四标签、完整赛后事件新增/修改/删除和真实结束时间修正。结束改早时保留并标记范围外事件、保存前展示影响，重算统计且不改写原始 Workout。
- 拒绝 HealthKit 或定位权限仍能保存比赛；缺失显示“未记录/不支持”，不能生成零或插值。Workout、原始心率和 GPS 保留在 HealthKit，业务库只保留非健康关联标识，健康数据不进入 CloudKit 或最小后台。
- 手机异常结束、离线待同步、原 Watch 迟到数据；正常换机、丢失设备七天等待；Apple 登录、身份与 iCloud 私有空间匹配、删除账号均属于 V1，不能降为上线后事项。
- 路线按真实位置、比例与方位展示，低精度/跳点过滤且断采分段；原始 GPS 不改。可选热图与赛后四角校准遵循最新原型规则并做真机验证，不承诺精确战术热图；无需赛前标定。
- V1 免费、无广告、无订阅、无场次限制；不加入静止五分钟自动暂停、分享海报、球队管理或付费实施。未来资格只保留既定后台边界，不扩大本期范围。

## 3. 模块与目录所有权

目录是原生工程的开发边界，按阶段实际创建，禁止为并行开发先铺空模块。正式产品名为球历 / `football-record`，`FootballRecord` 保留为工程技术名。

| 子代理职责 | 独占目录/文件 | 输出与约束 |
|---|---|---|
| 工程集成代理 | `native/FootballRecord.xcodeproj/`、`native/Configuration/`、`native/Apps/iOS/App/`、`native/Apps/Watch/App/`、`scripts/native/` | targets、schemes、entitlements、依赖装配、构建入口；其他代理不得直接修改共享工程文件 |
| 事件与仓储代理 | `native/Packages/MatchCore/`（含业务与 MatchStore targets） | 纯业务状态机、事件更正与重算；原子仓储、迁移、outbox、崩溃恢复；不导入 UI、HealthKit 或网络实现 |
| 采集与 Watch 代理 | `native/Modules/WorkoutCapture/`、`native/Apps/Watch/Features/` | Workout/权限/恢复、Watch 双页和触觉反馈；通过共享服务写事件，不另建比分事实源 |
| 设备同步代理 | `native/Modules/DeviceSync/` | WatchConnectivity 通道、分包、持久化 ACK、重试去重和终结状态传播 |
| 账号与后台代理 | `native/Modules/AccountKit/`、`backend/` | Apple 身份验证、激活设备、原子比赛锁、异常终结、迁移/删除、匿名统计；不存比赛内容或健康数据 |
| 私有云代理 | `native/Modules/CloudSync/` | CloudKit 私有 zone、变更令牌、检查点、冲突和删除传播；只同步业务数据 |
| iPhone 与分析代理 | `native/Apps/iOS/Features/`、`native/Modules/RouteAnalysis/` | 比赛/历史/生涯/设置、时间线编辑、MapKit 与上场区间分析；不绕过核心引擎修改统计 |
| 验收代理 | `native/UITests/`、`docs/native/validation/` | 集成回归、设备实测和证据；各模块单元测试仍由模块代理维护 |

核心使用可独立测试的 Swift package；其余先按模块目录组织，只有实际复用或构建边界需要时再拆包，不为并行而引入大量空 package。同时运行的代理不得拥有同一可写文件。并发槽位不足时按依赖排队；若任务横跨目录，由主代理先指定唯一集成责任人，其他代理通过接口或提交交接。

主代理只负责统筹、派工、审查与验收；原生代码、测试和工程变更交由子代理。子代理必须知悉共享仓库内存在其他协作者，不能撤销他人更改。

## 5. 里程碑与验收门槛

### M1：原生工程、共享事件引擎与可靠本地库

**依赖：** 本计划与工作流就绪；无需先等签名、CloudKit 容器或后台服务商。先由工程代理建立可构建壳与共享包入口，再由事件与仓储代理实现基础闭环。

- [ ] 创建 iPhone/Watch targets 与共享 packages；记录 Xcode/SDK、最低系统和可用模拟器；形成 `scripts/native/verify.sh` 的构建/测试入口。
- [ ] 明确 Match、MatchEvent、比分快照、sourceDeviceID、correctionOfEventID、revision、删除标记、终结事实和采集片段的契约；不在模型里保存另一份最终比分。
- [ ] 实现全部 V1 事件回放、比赛/上场时间交集、比分与完整/未出场/不完整/冲突的统计归属。真实时间与比赛时间均保存；UI 时钟由事实计算，不能依赖定时器每秒写库或只累加内存秒数。
- [ ] 同一事务保存 Match、事件、更正及 outbox；包含持久化失败不显示成功、重启重放、迁移、重复包、破损包可诊断恢复与检查点验证。清理 outbox 只以对端持久化 ACK 为依据。
- [ ] 持久化稳定开赛请求意图；真实锁未取得时不能写为已开赛。异常终结与更正从模型阶段纳入，不能先用不可变的“正常完成”布尔值埋下返工。
- [ ] 交付可注入时钟、故障与仓储适配的业务测试入口，供采集/同步/后台复用；Debug 模拟器明确标记“开发模拟”，替身不能进入正式开赛链路或作为 E2E 证据。

**自动验收：** 共享包测试覆盖首发/替补、多次上下场、暂停恢复、重复上下场、跨日、未闭合出场、进球/失球/乌龙/助攻、1000ms 防重复与撤销；事件插入/修改/删除/结束改早触发重算；incomplete/conflict 不进生涯；事务中途失败、进程重启、重复写入均不丢已确认事件。无签名 iOS/Watch 构建通过。

**交付：** 可构建工程、共享契约、持久化仓储与测试结果；不会据此宣称能记录一场真实比赛。

### M2：Watch 真实采集、原生记录 UI 与恢复

**依赖：** M1 契约和仓储通过。采集代理和 iPhone 基础 UI 代理可并行；共享工程注册统一交给工程代理。

- [ ] 实装双页 Watch、首发/替补选择、快记与撤销、暂停/继续/结束；iPhone 记录入口复用相同引擎和单写入者约束。
- [ ] 真实足球 Workout、心率、距离、速度、路线与权限状态；下场继续采集，比赛暂停与 Workout 暂停一致；仅存非健康 Workout 关联及片段信息到业务库。
- [ ] Watch 崩溃/重启优先恢复原 Workout；失败仍沿用原 matchID/recordingDeviceID，从恢复时刻续采并标缺口，不插值、归零或补造轨迹。
- [ ] 收到异常终结事实后禁止恢复继续采集；本地已有数据保留归入原比赛。
- [ ] 完成 iPhone 当前比赛、状态提示和历史骨架，不让显示端写入另一设备的活动比赛；无传感器/拒绝权限仍可记录。

**真机验收：** 配对 iPhone + Watch 证明真实授权、后台/熄屏运行、暂停/上下场、强制退出后恢复与恢复失败缺口；拒绝权限仍可保存。记录机型、系统、时间与观察结果。模拟器数值或 HealthKit stub 不计为采集通过。

**交付：** 可实测采集适配、双端原生记录页面、恢复报告；完整开赛锁链路仍等待 M4 的真实后台验收。

### M3：离线记录与 Watch/iPhone 持久化同步

**依赖：** M1；与 M2 适配可并行开发，跨设备验收需要 M2 真机包。

- [ ] 选择 WCSession 即时/后台文件等通道，应用协议统一包含 matchID、来源、revision、包序、checksum 与幂等键；传输成功不能替代接收端落盘确认。
- [ ] 发送端 outbox 重试、接收端事务合并与 ACK；重传、乱序、重复、分包、断连与重启不重复计分；发送端收到持久化 ACK 后才清理已确认待传数据。
- [ ] 区分“本地已保存、待传手机、待云同步、待后台终结”；离线正常结束保持 endedPendingSync，异常结束保持 incomplete 和待同步事实。
- [ ] 终结状态不可被旧包回滚：迟到 Watch 数据保留在原 matchID，不重新激活、不自动 completed、不改变 recordingDeviceID。

**自动与真机验收：** 故障注入覆盖发送后失联、接收落盘后 ACK 丢失、乱序/重复/校验失败与两端重启；真机断开配对通信后记录与结束，重新连接只出现一份事件。已确认删除的事件不能被旧包复活。

**交付：** 协议文档、双设备断连/恢复记录、可靠 outbox 与同步状态 UI。

### M4：账号、原子比赛锁、CloudKit、异常结束与设备生命周期

**依赖：** M1 契约；M3 的可靠业务传输用于完整联调。账号/后台代理与私有云代理可按固定契约并行。Apple Developer 配置及实际后台运行环境须在该阶段联调前就绪。

- [ ] Apple 登录与服务端身份验证；绑定当前 iCloud 私有空间，单激活 iPhone/多登记 Watch；身份或 iCloud 不匹配明确阻止错误恢复。
- [ ] 后台原子获取活动比赛锁，以稳定请求 ID 重试；已存在锁只恢复原比赛或进入手机异常结束。取锁超时后查询同请求结果，不能另建 matchID 绕过锁。
- [ ] 实接真实网络开赛；Watch 自身联网或经手机代理均需得到真实后台确认。锁成功而本地启动失败时，保留可恢复意图并通过相同请求对账，不能静默遗留不可解释的锁或生成第二场。
- [ ] 正常离线结束后补传并确认释放；手机异常结束先落盘，后台按账号、matchID、锁归属原子终结。重复请求幂等，旧比赛终结不能释放后来比赛的锁。
- [ ] CloudKit 自定义私有 Record Zone、变更令牌、revision、检查点、删除传播、配额/关闭 iCloud/账号变化处理；冲突保留事实并显式标记，不能静默最后写入覆盖。
- [ ] 正常换机强制旧机在线、无活动比赛、无待同步数据，最终检查点上传后新机下载校验再激活；丢失设备走已确认的七天等待与 Apple 再验证，不绕过活动比赛异常终结。
- [ ] 删除账号删除后台身份/设备/赠送资格；按用户选择分别处理 CloudKit 与本地数据，删除 App 创建的 HealthKit Workout 单独确认。断网或中途失败需显示进度并可幂等恢复，不把一处成功当成全部完成。
- [ ] 最小匿名统计及开关按方案实施；后台不可接收时间线、比分、球员/队名、健康数据、GPS/场地或真实 Apple ID/邮箱。

**自动验收：** 并发开赛只有一个锁；重试返回相同结果；正常/异常重复终结、旧设备迟到上传、新比赛已创建后的旧终结均不误释放；迁移限制和七天时钟边界；删号分项失败恢复；CloudKit 冲突/删改/配额故障不静默丢数据。

**真实 E2E 验收：** Apple 登录 → 真实联网锁 → Watch 开始 → 全程断网记录/结束 → 恢复网络 → 手机持久化 → CloudKit 同步 → 后台确认释放 → 新比赛允许开始。另测原 Watch 不可恢复时手机异常结束、离线提交/联网上传及旧 Watch 迟到数据。Debug stub、单机模拟请求或只在内存中释放锁不能算通过。

**交付：** 实际环境配置说明、接口契约、完整链路证据、换机与删除账号验收。该阶段所有能力均为 V1 发布条件。

### M5：完整赛后纠错、历史生涯、真实路线与分析

**依赖：** M1 重算口径、M2 HealthKit 关联、M3/M4 数据生命周期；UI 与合成样本分析可提前并行，最终以真实数据集成验收。

- [ ] 完成四标签、倒序历史与既定筛选、单场五区块、异常/未出场/冲突状态、生涯基础指标和设置/联系作者。联系入口复用已提供 QQ 二维码与邮箱。
- [ ] 时间线任意新增/修改/删除、球员与乌龙补录、真实结束时间修正；保存前说明范围外事件影响，保留原事件与原始 HealthKit 数据，重算比赛/出场/在场比分及生涯缓存。
- [ ] 从 HealthKit 获取真实路线和身体数据，按有效上场区间截取；缺权限、未采集、无路线或数据不足均有明确状态。详情出场时长按 HH:MM、距离(km) 按最新原型格式。
- [ ] MapKit 真实地理位置与等比例路线；按精度和跳点规则过滤展示，断采分段，底图不可用仍保留可信路线并提示；不把真实 GPS 发送到原型 OSM 请求链路。
- [ ] 可选热图按真实采样停留时间与“上场且运行”区间求交，以米制网格、淡黄橙红表达；无有效采样不生成热度。赛后四角/朝向、缩放、1 米微调、重复点禁存、附近复用/远处隔离及清除；不改原始坐标，不拉伸吸附。
- [ ] 单独报告原生可选热图、校准与实测定位质量；模拟原型表现不能当作真实场地精度。若实测不足，只显示已证实可用的路线/质量状态，是否改变已确认交付范围交回用户决定。

**自动与真机验收：** 与 M1 同一 fixture 重算一致；更正后各页面同步变化；缺数据三状态；合成 GPS 精度/漂移/缺口/暂停/替补席测试；至少在真实球场验证比例、方位、定位缺口、热图有效区间与校准，记录设备和误差观察，不承诺算法之外的精度。

**交付：** 可完整回看、纠错和恢复的比赛记录；原生页面、路线实测报告与统计口径说明。
