# WorkoutCapture

Actual reusable HealthKit/Core Location module for iOS 17+ and watchOS 10+, without App capabilities or project edits. Production start permission remains MatchSession's responsibility. A Workout is created only when MatchSession calls a durable `CaptureOperation` through `WorkoutGateway`.

The App's main-actor composition creates one `LiveMetricsChannel`, then `AppleWorkoutDriverFactory(metrics:)`, then `AppleWorkoutGateway(factory:)` and injects that gateway into its single MatchSession. Observe the metrics channel independently of SessionSnapshot. The channel, RoutePoint and live values are intentionally not Codable; no HealthKit values go to business SQLite/outbox or logs. iPhone heart rate is unsupported without a genuine source. The factory binds saved queries to `HKSource.default().bundleIdentifier` plus all original match/device/segment metadata.

Watch uses a local soccer/outdoor HKWorkoutSession, associated HKLiveWorkoutBuilder and real collected types. iPhone uses manual HKWorkoutBuilder and accepted Core Location samples; it never creates a primary HKWorkoutSession unavailable on iOS17. Manual pause/resume events are stored in HealthKit, paused locations are rejected and distance continuity breaks at resume. End drains previously accepted route samples, observes Watch stopped, ends collection, finishes once and ends Watch session after save proof. The route comes from the workout builder and is never separately finished.

NATIVE-010 must add actual HealthKit entitlement, Health share/update descriptions, location usage, Watch workout-processing mode and required iPhone location background capability. No Always authorization, audio or background-delivery capability is presumed. Watch's WKApplicationDelegate `handleActiveWorkoutRecovery` must invoke the existing MatchSession recovery path so candidate/binding ownership checks happen before this factory reattaches the original session/builder. It must not create a new session or call start/beginCollection during recovery.

All callback waits have deadlines. Timeout releases the caller but does not consume the first actual callback, clear a token, cancel a possibly committed save, or create another workout. Only one real callback is accepted; late actual callbacks update the same retained driver. Saved nil/nil is savedAwaitingLink, then a source/binding/token-checked query can provide the real UUID. Empty/error/locked reads remain unknown. Saved proof cannot regress under stale running/paused callbacks. Route insertion failure permanently closes that writer.

Limitations requiring device evidence: permissions/revocation, sensor support/samples, GPS background/lockscreen, pause semantics, lockscreen nil/nil saves, original Watch crash recovery, user force quit and device reboot are distinct pending checks. iOS17 cannot reattach a manual builder after process loss. If its saved query is hidden/empty, this implementation remains unresolved and cannot safely continue a new segment. A genuine saved UUID can close the original segment with recoveryUnavailable; MatchSession then decides continuation/gap. No fake nil,nil or query result proves real device acceptance. A stopped recovered Watch session also remains conservative about an unknown prior finish; it does not blindly finish again.
